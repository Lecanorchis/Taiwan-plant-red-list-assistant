# 臺灣維管束植物區域紅皮書評估

用單一 agent 跟使用者逐步評估。每次只處理一個末端分類群，將可恢復的狀態存入本機工作區。命令中的 `<cli>` 代表 `node <本技能目錄>/scripts/redlist.mjs`。開工前用 `<cli> list` 檢查既有清單，或先確認區域範圍再用 `<cli> init` 建立工作區。區域範圍要寫清楚納入的離島及其依據。

1. **建立清單及核對名稱。** 把使用者指定的分類群加入清單。`<cli> taxon` 回傳候選，須比對分類來源、接受名、異名、階層及概念。釐清同一種的種下單位後，用 `parentId` 表示重疊關係，只評估末端。跨來源查詢只採用已確認符合該分類概念的識別碼。
2. **確認適用性。** 確認區內野生族群、原生性、繁殖或保育引入歷史，依區域指引記錄適用、不適用或待查。先讀 [評估方法](references/method.md) 中的「適用性」。歷史名錄和全球類別可引用為背景，仍要逐項查證本次區域結論。
3. **建立證據。** 用 `<cli> sources [keyword]` 找準則和文獻。各項數字、主張與推論分別連結到可定位的證據。查分布時保存 API 快照，用 `review` 建立篩選表，請使用者核對範圍、野生及現存狀態、採樣偏差、紀錄重複與座標精度，再用 `range` 產生初步 EOO、AOO 與本機圖。查詢失敗、頁數達上限及零筆分別記錄。詳見 [工作區與 CLI](references/workspace.md)。
4. **區內初評。** 依 [評估方法](references/method.md) 查適用的 A–E 準則，逐項保存證據、結果及缺口。區分直接觀察、估計、推論、懷疑與推估。分布點可提供空間證據，數量、趨勢、威脅定義地點及嚴重破碎化各自需要依據。先與使用者核對可能類別和關鍵不確定性。
5. **區域調整及個人報告。** 檢視區外同分類群的繁殖體移入、區外族群趨勢與區內依賴程度。記下調整方向和理由。以 `<cli> report <id>` 產生草稿，取得使用者審閱後再填審閱者與日期，使用 `validate` 查缺項並重新輸出。遇到資料缺口，保留待評欄位及具體的待查問題。

在可執行命令的主機使用 CLI。在僅能讀檔或對話的主機，使用相同欄位協作，請使用者提供工具輸出或手動查核結果。對外分享前另核對來源授權、個資及敏感座標。個人工作區保存每次評估、觀測快照及地圖，公開程式庫保存技能、工具與可再散布的參考資料。
