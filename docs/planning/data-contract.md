# 評估資料與交換規格草案

狀態：設計草案 `0.1-draft`；尚未建立可執行 schema、資料庫或匯入器。以下欄位名稱、格式與範例用於討論，不宣稱相容於既有 CLI 的 JSON。

本文件與 [畫面流程](workbench.md) 一起閱讀。個人評估資料保存在本機；公開參考資料另行維護。使用者可以隨時保存不完整資料，不必先形成最終等級。

## 1. 共同原則

- 穩定識別碼不從學名衍生；改名不改 ID。示例 ID 為便於閱讀的代號，正式產生方法待實作時固定。
- 數值欄位有單位、狀態、估計範圍、方法與證據；未知使用 `null` 及原因，不以 `0`、空字串或 `false` 代替。
- 布林性判斷使用 `yes`、`no`、`unknown`、`not_assessed`；只有確有不適用意義的欄位才允許 `not_applicable`。
- 科學狀態與工作狀態分開。準則結果使用 `pending`、`insufficient`、`not_met`、`met`，不直接等同階段完成度。
- 原始資料、人工修正、計算結果、AI 建議與已採用判斷可相互追溯，避免用後來內容覆寫原始來源。
- 系統事件保存含時區的時間；評估日期、資料截止日另用日期欄位。來源只提供年份或月份時，保留其原精度，不補成確定日期。
- 引用皆指向穩定證據 ID；URL 與附件只是證據的一部分。來源未確認時保留待查。

## 2. 資料物件

| 物件 | 主要欄位與責任 |
| --- | --- |
| `Project` | `id`、名稱、評估日期、資料截止日、區域版本、分類名錄版本、規則版本、`revision`。 |
| `ListEntry` | 清單順序、分類概念 ID、評估 ID、暫停／封存狀態；父層整理項與實際評估項分開。 |
| `TaxonConcept` | 原始輸入、接受名、命名者、階層、上位概念、來源識別碼、分類處理來源與人工差異。 |
| `Assessment` | 一個分類概念在指定區域與時點的適用性、資料、準則、區域結果、工作狀態及 `revision`。 |
| `Source`／`Evidence` | 原始來源、授權、取得時間、頁碼或紀錄位置、可支持的內容、限制及證據關聯。 |
| `OccurrenceSnapshot` | 查詢來源與條件、原始頁面、下載時間、完成／部分／失敗狀態及資料完整性。 |
| `Occurrence`／`OccurrenceReview` | 標準化紀錄、原始定位、修正歷程、分類可信度、證據用途及空間用途。 |
| `SpatialRun` | 固定輸入版本、計算方法與參數、工具結果、限制及過期狀態。 |
| `AIRequest`／`AIProposal` | 交付 AI 的內容版本、任務與可建議範圍；匯入的原始回覆及逐項審閱狀態。 |
| `AuditEvent` | 變更前後值、修改來源、時間、理由，以及對應的請求／提案／證據 ID。 |
| `ExportRecord` | 產生的資料包類型、所含資料版本與檔案清單；不等同已證實外部檔案保存成功。 |

本機儲存另有 `localWorkspaceId`，作為資料副本的命名空間；它不是分類群 ID，也不作跨模型識別。還原成新副本時保留原專案與資料 ID，使用新的本機命名空間，不與既有副本混寫。

來源授權與檔案本體逐項保存，不由專案程式的 MIT 授權覆蓋。參考庫的完整內容不必全放入每份個人備份，但要保存已採用的名稱快照、規則版本、證據定位與分析所需的資料；未附檔的外部來源必須列明。

## 3. 評估欄位分組

「完成時需要」是個人查核的檢查規則，不是儲存或匯出條件。未取得資訊的欄位可用未知／資料不足與說明記錄；證據是否足夠仍需使用者判斷。

| 分組 | 欄位草案 | 個人查核重點 |
| --- | --- | --- |
| 基本設定 | `taxonConceptId`、評估日期、區域與版本、資料截止日、參考規則版本 | 明確知道評估哪個概念、區域與時點。 |
| 分類 | 原始名、接受名、命名者、種／亞種／變種、異名、TaiCOL taxon ID 與 name ID、其他來源 ID、人工處理理由 | 名稱與分類概念分開；人工處理附依據。 |
| 適用性 | `eligibility.status`（待確認／適用／不適用）、原生與野生狀態、繁殖或族群情況、理由及證據 | 名錄缺項或沒有觀測不直接等於不適用。 |
| 分布 | 區內分布摘要、歷史／現況、區外分布、採樣涵蓋、知識缺口、紀錄與計算批次 | 區內初評與區外影響使用的資料分開。 |
| 族群 | 成熟個體數與範圍、計數方法、次族群、無性繁殖計數、世代長度、趨勢與時間窗 | 紀錄筆數不當作成熟個體數。 |
| 生育地與威脅 | 生育地、棲地變化、威脅類型與時間、影響範圍、威脅定義地點及依據 | 地點判斷有威脅背景，與採集點或網格數分開。 |
| 準則 A–E | 每項狀態、輸入指標、適用條件、候選結果、準則代碼、理由、證據與不確定性 | 資料不足與不符合分開。 |
| 區內初評 | 工具候選、使用者採用的類別、成立代碼、理由、證據 | 人工採用結果與工具建議有明確區別。 |
| 區域調整 | 區外來源族群、有效移入、未來移入變化、依賴移入、調整方向與幅度、採用類別、理由 | 保留初評；無證據不推定有救援效應。 |
| 不確定性 | 問題、可能影響、所需資料、處理情況 | 允許帶有已交代的不確定性完成個人查核。 |
| 個人查核 | 各階段狀態、確認者自填名稱、日期、需重查原因 | 確認紀錄是本機個人聲明，並非官方審定或身分認證。 |

數值指標共用結構：`value`、`lower`、`upper`、`unit`、`valueStatus`、`method`、`period`、`evidenceIds`、`notes`。`valueStatus` 至少區分未評估、未知、測得、估計、推定與預測；依指標選擇適用值。對估計範圍的處理需明確記錄，不默默取中點當定值。

### A–E 輸入與規則

| 準則 | 預定結構化輸入 |
| --- | --- |
| A | A1–A4 子項、下降比例／範圍、世代長度、起迄與時間窗、下降證據、原因是否已停止／可逆／已知。 |
| B | 採用的 EOO／AOO 與計算批次、嚴重破碎化、威脅定義地點數、持續下降的項目、極端波動的項目。 |
| C | 成熟個體數、持續下降、C1 對應時間窗與幅度、C2 次族群數量／集中程度及極端波動。 |
| D | 成熟個體數；D2 另記受限分布、地點與可能在短時間造成高風險的威脅情境。 |
| E | 使用的定量模型、風險機率、時間窗、輸入與限制、來源；沒有分析時維持未評估或資料不足。 |

正式門檻、不等式、時間窗及組合條件由經核對的規則資料定義，本文件不另造一份未驗證門檻。實作規則需逐項連到官方章節，並以邊界案例檢查。方法參考 [現有方法文件](../../skills/taiwan-plant-red-list/references/method.md) 與 [IUCN 官方文件入口](https://nrl.iucnredlist.org/resources/redlistguidelines)。

NE、NA、DD、RE、EW、EX、LC、NT 及受脅類別均需適當的理由欄位與適用條件。未觸發數值門檻不自動得出 LC；沒有紀錄不自動得出 RE；工作完成狀態不由類別字串決定。

## 4. 紀錄、查核與空間分析

`Occurrence` 至少保留提供者、資料集、來源紀錄 ID、原始／標準化名稱、鑑定資訊、日期及其精度、原始地名、島嶼、座標、座標不確定性、模糊化、紀錄類型、野生／栽培與現存狀態、原始頁面或檔案位置、授權。

來源未提供穩定紀錄 ID 時，可建立本地 ID 並保留原始頁面與列位置；不把這種 ID 宣稱為來源提供。跨平台重複透過關聯群組處理，避免把相同座標的不同採集事件合併。

查核資料按「評估 ID＋紀錄 ID」保存，同一筆原始紀錄對不同分類概念或時點可有不同用途。

| 欄位 | 用途 |
| --- | --- |
| `identityDecision` | 分類歸屬已確認、排除或待確認。 |
| `evidenceUses[]` | 當前分布、歷史分布、分類查核、威脅或其他證據用途；可複選。 |
| `spatialDecision` | 本次空間分析採用、排除或待確認。 |
| `temporalInterpretation` | 與評估時間的關係、現存證據及限制。 |
| `scopeDecision` | 區內、區外或不確定，含地名與邊界版本依據。 |
| `corrections[]` | 修正欄位、原值、新值、定位或判定方法、不確定性、理由及證據。 |
| `reason`／`evidenceIds` | 查核依據；批次修改保留每筆受影響紀錄。 |

`SpatialRun` 保存採用紀錄及修正版本、查核版本、年代條件、區域版本、投影、網格尺寸及原點、演算法版本、輸入指紋、原始計算值、工具修正值、使用者採用值與理由。結果是不可變批次，重算建立新批次。

需檢查的情況包含零點、點數不足、共線、相同座標、跨島、模糊化與不確定範圍、查詢未完成、部分紀錄尚未查核。不能計算的項目使用空值與原因；不能把錯誤顯示為零。現有 16 組網格平移屬敏感度取樣，不能宣稱已找到所有可能原點中的最小 AOO。

## 5. 證據與參考資料

每筆證據包含 `id`、`sourceId`、書目／資料集、頁碼／章節／紀錄位置、來源主張、可支持的內容、限制、取得日期與附件。摘錄、轉述及評估者推論分開標示；AI 提出的推論不改寫成文獻原文。

參考庫維護來源版本、授權、雜湊、原文件、結構化內容與頁碼對照。評估保存當時採用的版本；新增名錄或準則版本不自動重寫既有評估。2017 結果另存歷史分類概念及當時範圍，名稱對照可一對多、多對一或未解。

初期來源為 [TaiCOL 政策](https://taicol.tw/zh-hant/policy)、[TBN v2.6 文件](https://www.tbn.org.tw/data/api/v26)、[2017 紅皮書授權紀錄](https://commons.wikimedia.org/wiki/File:The_Red_List_of_Vascular_Plants_of_Taiwan,_2017.pdf) 與 [IUCN 文件](https://nrl.iucnredlist.org/resources/redlistguidelines)。文件結構可借鑑 [ai-redlist-exam 的來源與轉換說明](https://github.com/shaneweisz/ai-redlist-exam/blob/main/data/iucn-guidelines/source/README.md)，實際納入前仍逐檔確認版本、授權與轉換品質。

## 6. 三種交換內容

副檔名是本輪建議。格式以內容中的 `format`、`schemaVersion`、`profile` 識別，不只依賴檔名。

| 類型 | 建議形式 | 內容 | 匯入行為 |
| --- | --- | --- | --- |
| 完整備份 | `*.tprla.zip` | 專案、清單、評估、原始快照、查核、計算、證據、歷程、AI 待審紀錄與本機附件。 | 驗證後還原成獨立工作副本。 |
| AI 任務包 | `*.tprla-ai.zip` | 一次任務的指引、選定評估內容、版本、相關證據與允許交付的附件。 | 交由 AI 閱讀；不冒充可完整還原的備份。 |
| AI 建議 | `*.tprla-proposals.json` | 任務 ID、原資料版本、建議項目、理由、引用與相依關係。 | 先進待審區，不直接更新評估。 |

完整備份的建議布局：

```text
manifest.json
project.json
list.json
taxon-concepts.json
assessments/<assessment-id>.json
sources.json
evidence.json
occurrences/records.ndjson
occurrences/reviews.ndjson
raw/<snapshot-id>/...
spatial/<run-id>.json
ai/requests.json
ai/proposals.json
history/events.ndjson
attachments/<file-id>
references/used-snapshots/...
```

`manifest.json` 包含格式、規格版本、`profile`、專案 ID、產生時間、應用程式版本、資料版本、檔案路徑、位元組數、SHA-256、媒體類型、必要／選用標記，以及只有外部連結而未附檔的來源。雜湊以封存檔內解壓後各檔案的原始位元組計算。

備份擷取同一個已提交的資料狀態，避免清單是新版、評估卻是舊版。生成失敗可重試，不修改原資料。雜湊用來發現損壞，不代表來源可信或已驗證使用者身分。

匯入先檢查檔案格式、版本、路徑、解壓大小、雜湊、ID 唯一性與引用完整性，再以單一交易建立新工作副本。限制值於效能驗證後固定。拒絕越界路徑、重複檔案路徑、損壞與不完整的必要內容；保留可閱讀的錯誤資訊。附件不自動執行，引用網址不在匯入時自動存取。

舊版格式透過已測試的遷移規則建立新副本。未知的較新版本不靜默丟棄欄位。還原的 AI 待審建議保留為歷史內容，重新確認任務依據後才能採用；第一版可要求重新產生任務以避免不同副本混用。

## 7. AI 任務包與建議範例

AI 任務包內至少有 `manifest.json`、`TASK.md`、`context.json`、建議格式說明及相關證據。任務說明包含要解決的問題、四類技能之一、允許的建議動作、已知限制與回傳格式。技能使用 Markdown，交換使用 JSON；模型品牌不作為匯入格式的必要條件。

匯出前讓使用者檢視資料清單。彙整通常只需要進度與待辦；分類需要名稱、概念與來源；分布可能需要紀錄與座標；評估需要採用指標、計算結果與證據。這些是預設選擇，實際交付內容由使用者決定。

以下 `context.json` 是縮減的虛構示例，展示欄位關係，不是有效備份或實際植物評估。格式中的示例參考版本須由正式資料取代。

## 8. 建議動作與審閱規則

| 動作草案 | 允許提出的內容 | 採用方式 |
| --- | --- | --- |
| `set_assessment_field` | 白名單中的敘述、指標、準則狀態、候選類別及理由。 | 顯示新舊值，使用者確認後寫入。 |
| `add_evidence` | 帶來源定位的新證據草稿。 | 使用者核對來源後採用；來源未解保持待查。 |
| `suggest_occurrence_review` | 紀錄歸屬、證據用途、空間用途與理由。 | 進入紀錄查核畫面，保留原始資料。 |
| `add_occurrence_candidate` | 額外蒐集的紀錄及來源。 | 先進候選匯入區，經格式、重複與人工查核。 |
| `add_task` | 分類爭議、資料缺口、建議重算或補查。 | 加入待辦；不直接改分類概念或計算結果。 |

這些動作是資料建議，不能攜帶可執行命令、任意檔案路徑或任意資料庫更新。欄位白名單不包含 ID、原始快照、規則版本、區域範圍、計算產物、人工確認者與完成狀態。未列出的動作以不支援提示處理。

匯入及採用順序：

1. 辨識格式與版本，確認目標專案和本機已發出的任務。
2. 檢查評估 ID、原版本、依賴的範圍／名錄／規則／計算，以及欄位與引用是否存在。
3. 建立待審提案，不改評估資料；重複匯入相同提案不得重複寫入。
4. 顯示舊值、新值、理由、來源與衝突；使用者接受、編輯後採用或略過。
5. 有相依關係的證據與欄位變更組成一個審閱群組，在同一交易中採用；相依提案被略過時，相關內容不能孤立採用。
6. 寫入修改歷程，增加評估版本，更新受影響的重查旗標。

第一次接受同一批次的部分建議後，其餘建議不能只因版本已增加就全部失效。審閱器需追蹤本批次已接受的變更；若其他輸入仍相同，可繼續接受獨立項目。發生外部修改、欄位舊值不符或相依資訊改變時，停止受影響項目並要求重查。跨頁籤修改同樣以交易與版本檢查處理，避免後寫覆蓋。

## 9. 版本與更新相依

`assessment.revision` 在已採用評估內容、查核決定或工作確認狀態變更時增加。只讀頁面、變更排序、匯出任務或收到尚未採用建議，不改變科學內容版本。專案層級另保存整體修訂與共同設定版本。

每個 AI 任務保存所交付檔案的雜湊及相依版本。回覆以 `requestId` 找回原始內容，採用時對照目前評估與相依資料；另一分類群的無關修改不必使本任務失效。任務包中內容的雜湊依原始 UTF-8 位元組計算，不能任意重新序列化後當成相同檔案。

改分類、範圍、紀錄或規則時，保留原結果並標示受影響內容需要查核，不自動擦除或自動重評。資料截斷、待查紀錄與證據缺口持續可見。

## 10. 本機保存與資料移轉

預定以 IndexedDB 保存結構化內容及附件。需要處理配額、寫入失敗、多頁籤、重新載入及格式升級；瀏覽器儲存不能視為永久備份。背景與限制見 [MDN 儲存配額與清除說明](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria)。

既有 CLI 工作區另設專用匯入步驟，先預覽名稱、範圍、證據與欄位差異，再建立新的網頁專案。無法自動對應的內容保留在舊資料附件與待處理清單，不偽造已遷移成功。既有工作區與草稿檔不由網頁設計階段修改。
