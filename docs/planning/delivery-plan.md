# 開發與驗收清單

本文件是 [設計規格](README.md) 的後續開發順序。所有項目目前均為待實作或待驗證，不以本文件存在表示功能已完成。尚未排定工期，實際估時須在來源、API 與資料量驗證後進行。

2026-11-13 已完成部分 [P0 來源與瀏覽器查核](feasibility.md)，並提出 [12 個試評情境與靜態草圖](pilot-scenarios.md)。P0 的地理範圍完整性、資料規模與正式部署等仍待驗證；下列產品功能尚未實作。

## 1. 交付順序

| 階段 | 工作項目 | 可驗收結果 | 依賴 |
| --- | --- | --- | --- |
| P0 規格與可行性 | 檢視畫面、欄位及交換格式；確認核心名錄、地理來源與授權；瀏覽器 API 存取試驗；定義代表性案例。 | 規格無重大歧義；來源與授權清單；API 可行性紀錄；案例清單。 | 本輪設計討論。 |
| P1 清單與本機資料 | 專案、名錄快照、清單展開與匹配、分類確認、本機保存、備份及還原骨架。 | 手動建立與修改清單，重新載入與備份還原後內容一致。 | P0 的資料識別與格式。 |
| P2 分布與證據 | TBN、CSV／GeoJSON、原始快照、紀錄查核、地圖與島嶼定位、證據、空間計算及過期提示。 | 真實案例可匯入、查核、重算與追溯；部分下載可辨識。 | P1；地理與 API 驗證。 |
| P3 評估資料閉環 | A–E 欄位、經核對的規則、候選結果、區域調整、完整性檢查及個人查核。 | 不使用 AI，完成一個分類群並匯出可恢復的資料包。 | P2；規則與方法驗證。 |
| P4 參考資料與 AI | 四類技能、文獻查詢、AI 任務包、建議匯入與逐項採用、版本衝突處理。 | 不同模型使用相同契約，建議有來源且須經審閱。 | 穩定的資料格式與 P3 工作流程。 |
| P5 試用完善 | 代表性案例、大量紀錄、跨瀏覽器、操作回饋、既有 CLI 資料遷移與使用說明。 | 已知限制明確，主要資料保存與科學判讀問題修正。 | 前述階段。 |

P1 即開始建立必要的 TaiCOL 快照；P3 必須具備對應規則與引用。P4 才擴充較完整的文件檢索與歷史資料，避免手動流程依賴尚未完成的 AI 功能。

## 3. 規格驗收案例

| 案例 | 必須觀察到的結果 |
| --- | --- |
| 輸入接受名、異名與相近拼字 | 保留原始輸入，異名可對應；模糊匹配待人選擇，不自動建立錯誤概念。 |
| 一個種包含亞種／變種 | 最小單位明確；父層不重複計入評估數；種級紀錄不自動分配到下位單位。 |
| 名錄沒有某離島的分類群 | 可保留未解項與文獻補入，不自動判成 NA。 |
| API 零筆、錯誤與半途取消 | 三種結果可區分；部分下載不顯示為完整樣本。 |
| 同一標本出現在多平台 | 可追溯來源並提出疑似重複；相同座標的不同紀錄不被一律刪除。 |
| 模糊座標與歷史地名 | 可保留證據用途，空間用途另行判斷；修正包含方法與不確定性。 |
| 少量／共線點與跨島分布 | EOO 等無法估算時有原因；方法與範圍可追溯；不以錯誤零值判定。 |
| AOO 很小但其他 B 條件未知 | 只提示有空間資訊，不自動完成 B 準則或推導受脅類別。 |
| 無族群資料或無觀測 | 不預設成熟個體數為零，不自動得到 LC、DD 或 RE。 |
| 區外有紀錄但移入影響不明 | 提示查核與不確定性，不僅依非特有性自動降級。 |
| 變更分類、紀錄或範圍 | 保留舊結果，受影響計算與判斷出現重新查核提示。 |
| 未完成評估後備份與還原 | 清單、原始資料、未解項、證據、歷程與附件均可恢復。 |
| 同一備份匯入兩次 | 建立獨立工作副本或提示已有副本，不靜默覆蓋與混併資料。 |
| 寫入配額不足或跨頁籤修改 | 顯示失敗／衝突，保留待處理輸入，不宣稱儲存成功。 |
| AI 回覆有效、過期或格式錯誤 | 有效者進待審；過期及錯誤者顯示原因；均不直接改評估。 |
| AI 一批獨立建議逐項採用 | 已採用內容有歷程，後續獨立建議可繼續審閱，衝突建議被擋下。 |
| AI 引用新證據或不存在的證據 | 新證據與相依內容一起審閱；不存在的引用不得當成已確認來源。 |
| 兩個不同模型處理同一任務包 | 均可讀同一格式；建議可不同，但共用工具的相同輸入計算結果一致。 |

方法驗證使用可公開或自行設計案例，不將未公開的 IUCN 考題或答案當作專案測試資料。

## 4. 來源整理與品質檢查

TaiCOL 快照先確認資料欄位、使用條款、分類階層、異名關係、taxon ID 與 name ID，以及所有指定島嶼的涵蓋。階層遞迴需有去重與循環檢查；缺失或衝突列入查核清單。

2017 紅皮書轉換保留原始學名與頁碼，不自動補齊原書沒有的敘述。學名、等級、準則代碼等關鍵欄位逐筆核對，另比對總數及各類別統計；名稱對照的不確定性另列。分類、範圍與方法不同的歷史結果，不直接作為族群趨勢。

IUCN 文件逐檔記錄來源、版本、授權與引用方式。表格、註腳、圖示及跨頁內容需人工抽查；可執行規則中的條件、時間窗與門檻全部對照原文，不能只依 PDF 文字抽取結果直接上線。

地理資料必須釐清陸域邊界、顯示底圖、搜尋範圍與島嶼索引的用途；沒有可靠邊界時，使用明示的不確定狀態與人工判讀，不以一張細緻底圖掩飾判定限制。

## 5. 既有程式重用與遷移

| 既有項目 | 重用方向與必要檢查 |
| --- | --- |
| 工作區與清單 | 參考既有評估欄位，改用穩定概念 ID 與瀏覽器儲存；不直接覆寫舊檔。 |
| TBN／GBIF 下載 | 檢查來源識別、分頁、完整性與瀏覽器存取；GBIF 擴充可在 TBN 閉環後加入。 |
| 人工查核 | 保留追溯能力，拆開證據與空間用途。 |
| AOO／EOO | 逐項驗證投影、輸入條件、網格原點及例外；保留敏感度取樣的實際限制。 |
| SVG／舊網頁地圖 | 可借鑑點位、網格與凸包互動，重新檢查來源與授權、島嶼涵蓋及可用性。 |
| 既有技能 | 保留方法與來源概念；四類技能在契約穩定後拆分，與原型版本並存或提供遷移說明。 |
| Markdown 草稿輸出 | 維持舊原型用途；本版不移植為網頁正式報告功能。 |

## 6. 暫不包含與仍待選定的事項

正式評估報告、PDF／Word、遠端個人資料庫、帳號、協作、互評、公開資料發布、自動將個人資料上傳、必須安裝的本機程式，均不列第一版交付。

實作前待選定的技術細節包含瀏覽器支援範圍、地圖底圖來源、離線快取程度、ZIP 大小限制、語言與框架版本、索引方式，以及 API 無法直接由瀏覽器存取時的轉接選擇。這些是可行性與實作決策，不影響已確認的免安裝、本機保存及人工審閱原則。

現階段不要求使用者先決定這些技術細節。先以案例和實測縮小選項，再將會影響操作、資料流向或授權的取捨提出討論。
